Problem. raw_invoke returns text, so every caller that cannot fit the default verdict schema rebuilds strict parsing, checkpoint discard, redraw and provenance itself. They have already drifted: criterion scoring discards and redraws, while claim-ledger decomposition does neither, so a resumed run would replay a malformed draw and fail on it again.

Solution. Give the judge one interface that takes the prompt and a strict parser and returns a parsed value with provenance. Checkpointing, discarding, bounded redraws and provenance move inside the judge.

  • Locality: the redraw policy lives in one place
  • Leverage: one interface, every assessor task
  • Closes the latent claim-ledger replay gap
  • Tests: one fake backend covers all callers
  • Deletes the reach-in getattr(judge,"response_cache")

Tests: an in-memory adapter. A real seam: three production adapters plus one fake.

Problem. The grader–generator independence rule is what makes harness output trustworthy, yet it is enforced in four places with different logic, and an injected backend skips the transport check entirely.

Solution. One factory owns route selection, the per-route independence policy, pacing and provenance wiring. Commands name a route and never assemble backends themselves.

  • Locality: the independence policy is in one module
  • Leverage: commands shrink to one call
  • No unchecked injected path
  • Tests: policy table, one adapter fake
Overlaps with runner/transport/*: the factory stays in harness/ (one-way import rule). Don't move transport adapters across that seam.

C · One resume checkpoint, bound to content

Strong local-substitutable (tmp dir) F6 known bug

  • harness/response_cache.py — ResponseCache, CacheBinding

Before — two resume modules

rubric grading (E5f)

pickle {meta, cells, verdict_cache}

meta = judge pin, rubric fingerprint, budgets, n, sections_dir (a path string)

A section replaced in place still resumes.

blind assessment

JSONL response checkpoint

binding = candidate hash, profile version, assessor pin, pack-set hash, n

Refuses a moved binding, naming every field.

After

Response checkpoint — deep

open(path, binding, resume) · take · record · discard_last · stats

The binding always carries a content hash of what is graded.

rubric grading: binding = candidate hash + rubric fingerprint + budgets
blind assessment: unchanged

The pickle and the verdict_cache dict are deleted.

Problem. Rubric grading keys its resume on a directory path rather than the bytes it graded, so a replaced section is silently mixed with verdicts drawn on the old text. Blind assessment already solved this with a second, better resume module.

Solution. Rubric grading resumes through the response checkpoint, with a binding that includes the content hash of the sections. One resume module, one refusal rule.

  • Fixes the F6 bug by construction
  • Locality: one resume module
  • Deletes the pickle scratch format
  • Tests: tmp-dir checkpoint, swapped section
Rubric grading is E5f. The DN blind assessment already has the correct behaviour, so this is integrity hygiene, not DN-path work.

Inside: record_type and advisory/blocking checks, numbered naming, atomic write, transitive binding.

Record modules keep their meaning and declare only their kind and predecessors.

Problem. Every link in the chain that ends in Stage A/B re-implements loading, type checks, numbered naming and predecessor re-hashing, with different strictness: load_comparison checks shape but does not re-hash its baseline, while the operator review does.

Solution. One module owns how a DN record is written and how it is loaded against its predecessors. Each record module declares its predecessors and keeps its own vocabulary.

  • Locality: one binding rule for the whole chain
  • Uniform strictness at every link
  • Tests: one tamper suite for all 7 kinds
  • Interface shrinks; 3 path helpers deleted
Conflicts with the documented decision in record_binding.py not to share fail-closed field readers. Reopen only the chain (write/load/bind), not the readers: their per-record exception types stay. Probably over the 400-line admission limit, so split it or route it through wayfinder. Touches PE-09, so admission rule 5 applies.

Top recommendation

A · Deepen the judge call

Every DN assessor call already goes through it, and the 2026-10-06 incident, where a trailing comma lost a 45-call run, shows it is the fragile path. Today the redraw-and-discard fix lives in one caller and is missing from another. Making it the judge's job raises DN reliability before 10 Nov at one seam, without touching the §17 call graph. C is the quickest separate win: a small ticket that closes the known F6 bug.
