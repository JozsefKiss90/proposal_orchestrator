## 4. Points to settle with the operator before writing code

- **Launcher form.** (a) A Python module in the bundle's roots (proposal: `runner/host_env.py`, run as `python -m runner.host_env --region eu-north-1 --secret-id proposal-orchestrator/env-config -- <command…>`): calls `GetSecretValue` once through boto3, validates the object, sets the five variables in a copy of the environment and replaces itself with the command (`os.execvpe`), so no value passes through a shell, a file or stdout; (b) a shell script with the AWS CLI and `export` lines (AL2023 has the CLI; `jq` is not guaranteed; values would cross the shell and could reach SSM output); (c) both, (b) wrapping (a). Proposal: (a). It runs under the bundle's Python 3.11 with its pinned boto3 and is unit-testable with an injected client.
- **Where the launcher gets its own Region and secret id.** The Secrets Manager client needs a Region before `AWS_REGION` is known. Options: (a) both are required arguments, no default; after the read the launcher refuses unless the secret's `AWS_REGION` equals `--region`; (b) Region from the instance metadata (IMDSv2, hop limit 1 per R11) — one more moving part and an untestable path off the host; (c) Region from `AWS_DEFAULT_REGION`. Proposal: (a); the secret id by name (`proposal-orchestrator/env-config`, export `SecretName`), which IAM matches against `…/env-config-*` the same way as the ARN.
- **What the launcher accepts.** Proposal: the value must be a JSON object of exactly the five agreed keys, all strings; `ORCHESTRATOR_PRODUCTION_MODE` must be `true` and `ORCHESTRATOR_DIAGNOSTIC_LEVEL` `metadata` (the launcher exists only for the private host); any other key, a missing key, a non-string, or a credential-shaped key name (`KEY`, `SECRET`, `TOKEN`, `PASSWORD`, as in `tests/test_aws_env_config_template.py`) is refused before anything is exported. Whether the preset must resolve (`get_transport_preset`) before exec: (a) yes — fail early, which means the launcher refuses the real secret until R9e adds `BEDROCK_CONVERSE_EU`; (b) no — leave it to the transport layer, which fails closed at first use. Proposal: (a), stated in the decision record as the R8-D3 dependency.
- **Precedence over the caller's environment.** (a) The secret's five keys overwrite whatever the caller set; (b) the launcher refuses when the caller's environment already sets one of the five keys to a different value; (c) the caller wins. Proposal: (b) — a disagreement between an SSM command and the secret is a configuration error to surface, not to resolve silently. `AWS_DEFAULT_REGION` is set to the same value as `AWS_REGION` (or refused if it differs), so boto3 clients that read either agree.
- **What "without logging" covers.** Proposal: the launcher prints nothing on success; on failure it prints the failure kind and key **names** only (never a value, never the response object, never boto3's raw exception text for a parse error); it does not configure logging and does not pass values in `argv`. Tests capture stdout, stderr and `logging` records (and the exec'd command's argv) and assert that none of the five values appears, using distinctive sentinel values.
- **AWS_REGION refusal: where.** The ticket: "production mode refuses to run when `AWS_REGION` is missing." Options: (a) in `resolve_provider_config` (both paths) for `bedrock_converse` under production mode, plus `build_converse_backend` refusing to default; (b) only in `build_converse_backend`; (c) also in the launcher. Proposal: (a) + (c): refuse at resolution (so `runner/__main__.py` fails before any phase) and at build; remove the silent `us-east-1` default under production mode; keep non-production behaviour unchanged except that the preset's `default_region` is applied when `AWS_REGION` is unset (fixes fact (3), which today makes `BEDROCK_CONVERSE_US` work only by coincidence). `AWS_DEFAULT_REGION` alone does not satisfy production mode (F4).
- **F6.** (a) `bedrock` leaves `PRODUCTION_BACKENDS`; `BEDROCK_EU_PRODUCTION` becomes `production_suitable=False` (or is renamed — proposal: keep the name, flip the flag, note why); the tests that pin today's behaviour change in the same commit; (b) keep the code, and the guide states that only `bedrock_converse` is valid on the private host. Proposal: (a) — it is the only form a test can enforce, and the ticket says "code only". Check first who uses `BEDROCK_EU_PRODUCTION` outside tests (grep `runner/`, `harness/`, `tools/`, `plans/`).
- **`offline_bundle verify` and `ALLOWED_REGIONS`.** `verify` accepts `AWS_DEFAULT_REGION` alone and checks `ALLOWED_REGIONS` (no eu-north-1). Options: (a) R9 makes `verify` require `AWS_REGION` (the variable the backend reads), leaving the region list to R9e; (b) leave `verify` wholly to R9e. Proposal: (a) — one Region rule for production mode across the transport and the bundle check; R9e then only widens the list.
- **The deployment guide.** The ticket names the guide's variables. Options: (a) R9 edits only the guide's environment-variable blocks (`AWS_DEFAULT_REGION` → `AWS_REGION`, `SKILL_MODEL` → `ORCHESTRATOR_TRANSPORT_MODEL`, the launcher instead of `export` lines), leaving every other correction (ids, account, region values) to R13; (b) R9 changes no document and records the exact corrections for R13 in its decision record. - **Tests and names.** Proposal: `tests/test_host_env_launcher.py` (launcher: valid object → exec with the five variables and no output; each refusal; sentinel values never printed; `GetSecretValue` the only client call; the field name assembled, F-R8-8), additions to `tests/test_production_mode.py` (missing `AWS_REGION` refused at resolution and at build, both paths; `AWS_DEFAULT_REGION` alone refused; F6), `tests/test_transport_presets.py` (preset `default_region` applied outside production mode), `tests/test_offline_bundle*.py` if `verify` changes.
